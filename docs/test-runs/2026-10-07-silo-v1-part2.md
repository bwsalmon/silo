## 3. Leader: two replicas on one Postgres (step 3)

Replica A (`--listen :18080 --gateway-socket`) and replica B
(`--listen :18083`) shared one database and one fake.

| Step | Result |
|---|---|
| start A, then B | A logs `is the leader, epoch 2` (A had been restarted once). B serves and waits |
| pause the fake, insert `slow1` through the gateway (A) | operation `RUNNING`, `facade_operations.replica` = A, charged |
| `kill -9` A | **B takes the lease 2 s later, `epoch 3`**, runs the reconcile (7 objects, 0 orphans) |
| ~22 s later (A's heartbeat older than `ReplicaTimeout`) | B: `adopted 1 operations of replicas whose heartbeat stopped`. The row's replica is now B |
| resume the fake | the adopted op is marked done and its charge settled. B serves `slow1` as `RUNNING`, and its delete through B returns the charge |
| restart A. `SIGSTOP` the leader B, `pg_terminate_backend` its advisory-lock session | A takes the lease, `epoch 4` |
| `SIGCONT` B | B logs `lost the lease (epoch 3): leader work stops` at once. It noticed before any duty ran, so it attempted no stale write |
| the leader's adopt duty, run against the live database as a term of epoch 3 (an uncommitted probe calling `facade.Adopt` with `leader.Guard`) | **refused**: `leader: no longer the leader (the leader epoch moved on): epoch 4, this term's is 3`. As epoch 4 it runs |

The epoch fence can't be shown with the binaries alone: a stalled leader
finds out it lost the lease as soon as it wakes, before its next guarded
write. The probe runs the same guarded write the stalled leader would
have.

## 4. Egress proxy (step 4)

`silod gateway --egress-listen 127.0.0.1:13128`. The root was
bootstrapped with egress `allow [example.com:443, other.example:443]`. A
root can only narrow its own egress (`a silo may only narrow its own
egress: * is not in its allow list`), so the root's allow list is set at
bootstrap. `silo patch /a --egress-allow example.com:443`, then `curl -x
… https://<host>/` from each silo's address:

| From | `example.com` | `other.example` |
|---|---|---|
| `/` | 200 | 200 |
| `/a` | **200** | 403 |
| `/a/c` (own policy empty) | 403 | 403 |
| `/b`, `/b/d` | 403 | 403 |

- **Inheritance.** Every level must allow a host.
  - With `/a/c`'s own allow set to `example.com:443`, `/a/c` gets 200.
  - `--egress-allow other.example:443` on `/a/c` is refused with
    `LOOSER_THAN_PARENT: egress host other.example:443 is not allowed to
    the parent`.
  - A deny of `example.com:443` on `/a` turns both `/a` and `/a/c` to
    403. The header reads `Silo-Egress-Refusal: … denied by
    "example.com:443" in /a's egress policy`.
- **Port.** Plain `http://example.com/` (port 80) from `/a/c` is refused:
  `not allowed by /'s egress policy`.

## Findings

1. **`silod serve --fake-gce` still couldn't make anything** (part 1's
   finding 2), on `7819e615d`.
   - **Reproduction**: `silod serve --store sqlite:s.db --migrate
     --listen 127.0.0.1:18080 --host-project hp --fake-gce
     --dev-caller-header`, bootstrap the root, then insert a subnetwork
     with `network: global/networks/default`. The answer is 400 `The
     resource '…/networks/default' was not found`.
   - **Fixed**: `devFake` makes the host VPC `silo` (enforcement order
     `BEFORE_CLASSIC_FIREWALL`, as install does).
   - **Test**: `TestDevFakeHasHostVPC`.
2. **No instance could be made from a template unless the facade's
   endpoint was `silo.internal`.**
   - **Cause**: the facade writes selfLinks on `--facade-endpoint`, but
     `inLink` accepted full URLs only on `silo.internal`,
     `www.googleapis.com` and `compute.googleapis.com`. An instance from
     a template merges the template's properties as the tenant sees them,
     so the network arrives as the facade's own URL, and `inLink` read
     that URL as a bare network name.
   - **Effect**: on any other endpoint, every `instances.insert
     ?sourceInstanceTemplate=` failed. The same goes for any tenant that
     sends back a link the facade gave it.
   - **Reproduction**: `silod serve --facade-endpoint
     http://127.0.0.1:18081/compute/v1/ …`. Insert a global template with
     `networkInterfaces[0].subnetwork`, then `POST
     …/instances?sourceInstanceTemplate=global/instanceTemplates/tpl1
     {"name":"x"}`. The answer is 400 `The resource
     'projects/silo-<id>/global/networks/http://127.0.0.1:18081/compute/v1/projects/silo-<id>/global/networks/default'
     was not found`.
   - **Fixed**: `inLink` maps a link on the facade's own base to GCE's
     first. Another silo's link on that base is still 403.
   - **Test**: `TestNaming`, which fails without the fix.
3. **A silod on a fake `--compute-endpoint` called Google's Cloud Quotas
   API.**
   - **Cause**: the leader's hourly root-capacity refresh read
     `cloudquotas.googleapis.com` with whatever credentials were about,
     here the stub's dummy token, which got a 401. Only `--fake-gce`
     turned the refresh off.
   - **Why redirecting alone isn't enough**: pointing the refresh at the
     fake made it worse. The fake reports no quota it wasn't given, which
     the refresh reads as no capacity, so it set the root's granted
     capacity to 0 under 16 delegated vCPUs.
   - **Fixed**: the real client's Cloud Quotas endpoint follows
     `--compute-endpoint` to the fake's root (where `fake.Server` serves
     it), and the refresh is skipped there as it is for `--fake-gce`.
   - **Reproduction**: run silod with `--compute-endpoint <fake>` and
     watch the leader log `rootcap: cloud quotas: googleapi: Error 401`
     (or the stub proxy log `CONNECT cloudquotas.googleapis.com:443`).
   - **Test**: `TestGCPOptionsKeepQuotasOnTheFake`.
4. **The fence API's Postgres cases still didn't run in CI** (part 1's
   finding 1). The `postgres` job now runs `go test -run TestPostgres
   ./pkg/silo/fenceapi/` as well (about 13 s).

## Changes on this branch

- `cmd/silod`: `--fake-gce` makes the host VPC (finding 1).

## Observations (not changed)

- **selfLinks behind `silo proxy`.** They name the facade's endpoint
  (`http://silo.internal:8080/compute/v1/…` by default), not the proxy's
  `http://localhost:8642/…`. The facade takes them back, so a request
  that names one works through the proxy. Whether gcloud or terraform
  ever *dereference* a selfLink (for example an operation's) outside the
  cloud, where `silo.internal` doesn't resolve, wasn't tested. That needs
  the real tools against a live front door.
- **Stalled-leader fencing.** It isn't observable with the binaries
  alone: lease loss is noticed on wake, before a guarded write. See §3
  for the probe.
